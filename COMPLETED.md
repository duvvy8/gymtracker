## Disclaimer for the other agent

- **Do not hand-edit `BODY_HEATMAP_REGIONS` or `BODY_SILHOUETTES` in
  `src/data/bodyHeatmap.ts`.** Those path lists are generated by tracing the
  approved line art, not written by hand. Nudging a coordinate will drift the
  fill off the drawing. If a region is wrong, change the boundary that defines
  it and retrace, or say so in `UPCOMING.md` and hand it back.
- **The tracing tool is not in the repository.** It lives in Claude's scratch
  directory, so it is not available to you. Ask before assuming geometry can be
  regenerated on demand.
- **The anatomy PNGs are fixed.** `scripts/check-workouts.mjs` pins their
  SHA-256 hashes. They must not be regenerated, restyled, cropped, recompressed
  or combined into a sprite sheet.
- **The region ids, the region to view mapping, the aliases and the view
  selection are unchanged from the staged groundwork.** Only geometry and
  colour changed. Adding a region to a second view will change which views a
  machine renders and will break the assertions in `check:workouts`.
- **Colour lives in one place.** `heatMixForPercent` and `heatFillForPercent`
  in `src/lib/heatmap.ts` are the only mapping from a percentage to a fill.
  Anything that needs a heat colour should use the tokens through those
  functions rather than introducing new colours.
- **`docs/anatomy/manifest.json` is stale on purpose.** It records the
  five-band scale that shipped with the supplied asset pack. It was left exactly
  as supplied because it is an input artifact; the application does not use it.
  `docs/anatomy/IMPLEMENTATION.md` explains the supersession.

### J. Colour model reworked after looking at comparable products — 2026-09-07

- Research: Fitbod scores every muscle group from 0 to 100 percent and colours
  a body map from that score; MuscleSquad's heatmap draws frequently trained
  muscles darker and neglected ones lighter; the MuscleMap SwiftUI SDK fills
  unhighlighted muscles with a default tone, supports continuous or discrete
  intensity, interpolates along a named colour scale, and ships a legend view
  with min and max labels; the Fitness Visuals component exposes a small set of
  runtime colours plus tap to identify.
- The idea worth taking was the base fill. Previously untrained muscles were
  left as empty paper, so the map read as a few coloured patches floating in an
  outline. The figure is now filled with `--color-muscle-base` first, which
  gives the trained muscles something to stand out against and makes "not
  worked" an explicit state.
- The scale changed from one colour at varying opacity to a proper sequential
  ramp: `--color-heat-soft` to `--color-heat-strong`, interpolated in oklab with
  `color-mix`, still continuous and still driven by the percentage on the same
  1.25 curve. Solid fills replace transparency, so nothing looks washed out and
  the low end is a deliberate colour rather than a faded one.
- `BODY_SILHOUETTES` was added to `src/data/bodyHeatmap.ts`, traced from the
  same line art as the muscles so the base fill lands inside the drawn contour.
- The legend now shows the "Not worked" swatch alongside the Less to More ramp.
- Files touched: `src/data/bodyHeatmap.ts`, `src/lib/heatmap.ts`,
  `src/components/MuscleHeatmap.tsx`, `src/styles/tokens.css`,
  `scripts/check-workouts.mjs`, `docs/anatomy/IMPLEMENTATION.md`.
- Verified in the running app on Leg Press and Lat Pulldown at 320, 400 and
  1440 pixels: layers still share an identical box, no horizontal overflow, and
  a fresh tab reports no console errors. `check:all` and `npm run build` pass.
